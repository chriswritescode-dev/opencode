# OR-45: queued media streams emit only terminal events, with no per-poll progress observation

TypeScript: `packages/ai/src/generation.ts:43-58` defines the `generation-progress` observation and the `Event` union that adds `generation-finished`. `Generation.events` (`:123-145`) emits one observation per status refresh, starting with the current snapshot and ending after the first terminal one, and `resultEvents` (`:161-184`) streams those observations and then the expanded result. The shared media client routes a queued `stream` through `resultEvents` (`packages/ai/src/media-client.ts:62-68`), so `stream` is typed `Stream<Event | Observation, AIError>` (`:13-18`) for every modality built on it, and `Generation.events` is a public method callers can use directly.

Rust: `Generation::await_result` (`crates/ai/src/media/generation.rs:112-137`) refreshes status in a loop and returns only the terminal `Response`; `Generation` exposes no `events` stream and no progress event type, only the single `refresh` at `:91-99` and the `progress` field on a snapshot. For a queued route the shared media client starts the generation, awaits the result and maps `response_events` only (`crates/ai/src/media/client.rs:132-172`), and the modality streams are typed by their terminal events alone: `ImageClient::stream` returns `ImageEvent` (`crates/ai/src/modalities/image.rs:342-362`), `SpeechClient::stream` returns `SpeechEvent` (`crates/ai/src/modalities/speech.rs:319-341`) and `TranscriptionClient::stream` returns `TranscriptionEvent` (`crates/ai/src/modalities/transcription.rs:359-382`). A queued generation therefore produces no `generation-progress` observation and no `generation-finished` event, and no mid-poll emission of any kind reaches a stream consumer.

Reason: the port keeps generation polling behind `await_result` and lets each modality define its own terminal event list, so progress is only observable by calling `Generation::refresh` directly; TypeScript exposes it as a stream surface that `stream` interleaves automatically. Replay asserts what remains: queued video runs `Generation::await_result` with a recorded interval and compares the recorded sleep durations and result (`crates/ai/tests/all/replay.rs:517-547`), while image and transcription replay compare the complete recorded event list against the terminal events (`:445-461`, `:888-903`). No cassette contains a `generation-progress` observation, so neither the observation stream nor its cadence is exercised.
