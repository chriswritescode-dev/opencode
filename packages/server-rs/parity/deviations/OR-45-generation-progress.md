# OR-45: queued media streams emit only terminal events, with no per-poll progress observation

TypeScript: `packages/ai/src/generation.ts:43-58` defines the `generation-progress` observation and the `Event` union that adds `generation-finished`. `Generation.events` (`:123-145`) emits one observation per status refresh, starting with the current snapshot and ending after the first terminal one, and `resultEvents` (`:161-184`) streams those observations and then the expanded result. The shared media client routes a queued `stream` through `resultEvents` (`packages/ai/src/media-client.ts:65-68`), so `stream` is typed `Stream<Event | Observation, AIError>` (`:15`) for every modality built on it, and `Generation.events` is a public method callers can use directly.

Rust: `Generation::await_result` (`crates/ai/src/media/generation.rs:112-138`) refreshes status in a loop and returns only the terminal `Response`; `Generation` exposes no `events` stream and no progress event type, only the single `refresh` at `:91-99` and the `progress` field on a snapshot. For a queued route the image, speech and transcription clients each start the generation, await the result with `Generation::await_result` and map `response_events` only (`crates/ai/src/modalities/image.rs:337` and `:344-366`, `crates/ai/src/modalities/speech.rs:314` and `:321-344`, `crates/ai/src/modalities/transcription.rs:352` and `:359-382`); the shared helper that would do this, `media::client::operations` (`crates/ai/src/media/client.rs:94-222`), has no callers, and the video client has no generate or stream method, so video replay drives `Generation::await_result` directly (`crates/ai/tests/all/replay.rs:530-535`). The modality streams are typed by their terminal events alone: `ImageClient::stream` returns `ImageEvent`, `SpeechClient::stream` returns `SpeechEvent` and `TranscriptionClient::stream` returns `TranscriptionEvent`. A queued generation therefore produces no `generation-progress` observation and no `generation-finished` event, and no mid-poll emission of any kind reaches a stream consumer.

Reason: the port keeps generation polling behind `await_result` and lets each modality define its own terminal event list, so progress is only observable by calling `Generation::refresh` directly; TypeScript exposes it as a stream surface that `stream` interleaves automatically. Replay asserts what remains: queued video runs `Generation::await_result` with a recorded interval and compares the recorded sleep durations and result (`crates/ai/tests/all/replay.rs:517-549`), while image and transcription replay compare the complete recorded event list against the terminal events (`:444-452`, `:887-895`). No cassette contains a `generation-progress` observation, so neither the observation stream nor its cadence is exercised.
