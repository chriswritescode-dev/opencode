# OR-44: WebSocket failures omit readyState and OS codes, and the HTTP fallback context is unused

TypeScript: `packages/ai/src/route/transport/websocket.ts:89-100` fails a socket already closing or closed with `WebSocket closed before opening (state ${ws.readyState})`, and `waitOpen`'s error handler lifts the system code from the cause (`ENOTFOUND`, `ECONNREFUSED`) with `systemCode` (lines 77-80, 121-136). `packages/ai/src/protocols/open-responses-channel.ts:146-149` logs a warning when a WebSocket-capable endpoint falls back to HTTP. Its `execute` records the HTTP fallback's `HttpContext` in `fallbackHttp` and returns it from `execution.http`, preferring it over the WebSocket execution's own context (lines 167-192) (pinned commit `73a0eae88de47f10068a0f9dc7a743638fa3d830`).

Rust: `crates/ai/src/route/transport/websocket.rs` has no close-before-open state message; `read_stream` reports `WebSocket closed with code {code}` and `connect_error` (lines 386-396) leaves `code` as `None`, so OS codes are not lifted. `crates/ai/src/protocols/open_responses_channel.rs` has no logging path. `ChannelExchange.fallback` is populated by `crates/ai/src/route/client.rs:129-134`, but `direct_execution` in `websocket.rs` never calls it, and `ChannelExecution.http` stays `None` because `open` sets `http: None` (lines 140-146); `client.rs:141` therefore carries `None` on the channel path. Session rotation and connection affinity are left to the future session executor; `WebSocketInterceptor` in `crates/ai/src/route/transport/channel.rs:73-85` is a synchronous transform rather than a policy hook.

Reason: `tokio-tungstenite` exposes a connection rather than a browser-style socket with `readyState`, and the client currently opens a fresh socket per exchange. The fallback exists so a future session executor can choose it, but nothing decides to. The tests in `crates/ai/tests/all/websocket.rs` and the channel cassettes cover the connect URL, handshake headers, sent frames, observations and reasons; they do not assert error text, OS codes or `HttpContext` identity.
