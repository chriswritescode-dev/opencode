# OR-45: the corpus normalises transport noise and replay skips some byte comparisons

TypeScript: `packages/ai/test/recorded-test.ts:81-106` wraps the pinned package's `RequestExecutor` with `HttpRecorder.layerFetch` and `HttpRecorder.layerWebSocketConstructor`, storing one JSON cassette per scenario under `packages/ai/test/fixtures/recordings`. Each cassette holds the recorded HTTP or WebSocket interactions: request method, URL, headers and body, then response status, headers and body (`packages/http-recorder/src/cassette/store.ts:69-79`, `:113-125`). The recorder replays a cassette when it exists and records live traffic when it does not; `CI` makes a missing cassette fail instead of recording (`packages/http-recorder/src/replay/state.ts:5-18`), and a request matching no recorded interaction fails the replay (`packages/http-recorder/src/http/recorder.ts:84-144`).

Rust: the corpus exporter (`script/gen/llm.ts:158-171`) requires a recording under the pinned `packages/ai/test/fixtures/recordings` for every scenario and a scenario for every recording, and `script/llm/capture.ts:931-957` replays each recording through the pinned package's `RequestExecutor` under `HttpRecorder.layerFetch`, wrapping `LLMClient` (`:942-948`) and the modality clients. A cassette holds the TypeScript-encoded request (`:530-547`), model descriptor (`:549-569`) and emitted events (`:797-807`), not transport bytes alone. `script/llm/capture.ts:347-357` deletes an empty `providerOptions` object from a descriptor's `options`/`modelOptions` before recording, `:428-445` with `:315-340` replaces every multipart boundary with `----OpenCodeFixtureBoundary` in body and `content-type`, `:342-345` and `:437-453` base64-encode `Uint8Array` and other non-text bodies, and `:414-421` forwards a request that arrives outside an active step without recording it, covering the Google Interactions DELETE cleanup at `script/llm/scenarios.ts:2288-2312`. Four scenarios set `descriptorOnly` and omit `provider` (`script/llm/scenarios.ts:4575,4612,4639,5044`): three WebSocket channel cassettes and the bedrock thinking-binding cassette, so `capture.ts:466-470` builds no provider model and `:987` skips the provider-built descriptor comparison. For a media (`operation`) step the exporter compares the recorded model with the provider-built model only on `id`, `provider` and `route.id` (`capture.ts:989-995`); for a language step it compares the full encoded descriptor (`:997-1002`). `script/llm/providers.ts:70-85` captures each provider entry's first prepared request (`:498`) through a middleware that answers 599; its media descriptors are `{provider, routeId}` (`:410-411`) while language descriptors omit `options`, `modelOptions`, `transport` and `auth` (`:413-428`). Only the kind the default settings build is exercised per specifier (`:528-535`), so transcription, speech and decision entrypoints sharing a root are not all covered, and Bedrock `profile` has no case because it resolves through the AWS default credential chain, which the cleared `AWS_*` environment (`capture.ts:34-53`) cannot supply. `script/llm/realtime.ts:35` drops the `b3` and `traceparent` harness headers and `:46` replaces the multipart boundary. In replay, `crates/ai/tests/all/replay.rs:753-782` concatenates consecutive speech `audio-delta` chunks before comparing, because binary Deepgram chunk boundaries follow the transport; `:1244-1250` stops after the byte comparison when either prepared body is not JSON, still comparing method, URL, headers and body bytes at `:1229-1243`; and `:529-543` replays the recorded video sleep schedule produced by the 10 ms manual poll loop at `script/llm/scenarios.ts:2976-2988`. Language replay compares `model.descriptor()` with the recorded descriptor ignoring `auth` (`crates/ai/tests/all/replay.rs:95-100`, `without_auth` at `:104-109`), as the OR-45 plan specifies: Rust `describe_auth` (`crates/ai/src/route/model.rs:205-231`) describes provider-built environment, optional and compound credentials as `{"type":"none"}` where TypeScript records `bearer` or `header` with the value, and Rust SigV4 descriptors carry `"sessionToken": null` where TypeScript omits it (`crates/ai/src/route/auth.rs:398-416`); the rendered request headers are still compared exactly. Coverage stops at the recordings: the eleven transcription cassettes record only successful generations, so the error branches at `replay.rs:918-1000` never run; the `zai-coding-plan` routes have no cassette and are covered by `crates/ai/tests/all/providers.rs:327-344`; the Seedance video protocol has no recording and is covered by tests transcribed into `crates/ai/tests/all/media.rs:401-860`.

Reason: these are recorder and replay normalisations for noise the transport generates — random multipart boundaries, trace headers, arbitrary audio chunk sizes, non-JSON bodies — not tolerances in the port's behaviour. After normalisation the server's own output is still compared exactly: request method, URL, headers and body bytes, the model descriptor apart from `auth`, every emitted event and, for speech, the concatenated audio. The `auth` exclusion exists because Rust `describe_auth` cannot name provider-built optional, environment or compound credentials, and its SigV4 shape always serialises `sessionToken`; the rendered request headers are still compared, so credential application is covered. Every cassette replays: `crates/ai/tests/all/replay.rs:1588-1635` fixes the count at 313 and fails on any cassette that panics, and the omissions above are cases with no recording to replay, not cases it ignores.
