# OR-44: provider options and stream frames decode leniently, with protocol-named errors

TypeScript: `packages/ai/src/route/client.ts:352-363` decodes every frame with the protocol's `stream.event` Effect schema and, on failure, reports `Invalid ${provider}/${route.id} stream event` (the prefix comes from `client.ts:412`) while setting the error's `route` field to the route id (`packages/ai/src/protocols/shared.ts:196-199`). Provider options also go through schemas, so a malformed known field fails the request where the schema is strict, for example Bedrock `thinking` in `packages/ai/src/protocols/bedrock-converse.ts:501-538` and Anthropic options in `packages/ai/src/protocols/anthropic-messages.ts:367-384`, while Gemini opts into per-field `lenient` at `packages/ai/src/protocols/gemini.ts:155-168` (pinned commit `73a0eae88de47f10068a0f9dc7a743638fa3d830`).

Rust: provider options are hand-decoded. Gemini's `decode_options` (`crates/ai/src/protocols/gemini.rs:53-63`) and Bedrock's `decode_options`/`decode_thinking` (`crates/ai/src/protocols/bedrock_converse.rs:660-686`) drop a malformed known value with `and_then` instead of failing. Stream frames are parsed as `serde_json::Value` (`crates/ai/src/protocols/openai_chat.rs:70-73`, `crates/ai/src/protocols/bedrock_converse.rs:801-809`, `crates/ai/src/protocols/gemini.rs:880-889`); a frame that is valid JSON but violates the provider schema is accepted, producing fewer fields or no events, and Bedrock defaults a missing `contentBlockIndex` on `contentBlockDelta`/`contentBlockStop` to 0 (`crates/ai/src/protocols/bedrock_converse.rs:928,946`) where the TypeScript schema requires it (`packages/ai/src/protocols/bedrock-converse.ts:206,216,236`). Invalid-frame errors are built by `crates/ai/src/protocols/shared.rs` `event_error` with hardcoded protocol names: `Invalid openai-chat stream event` (`crates/ai/src/protocols/openai_chat.rs:72`), `Invalid anthropic/anthropic-messages stream event` (`crates/ai/src/protocols/anthropic_messages.rs:1503`), `Invalid bedrock/bedrock-converse stream event` (`crates/ai/src/protocols/bedrock_converse.rs:769`) and, for Gemini, a schema-invalid event with `Invalid {provider}/{route} stream event` and the error's `route` field set to `ID` (`crates/ai/src/protocols/gemini.rs:1104-1107`). A non-JSON Gemini frame instead uses the runtime route id as its `route` and the runtime label in the message (`crates/ai/src/protocols/gemini.rs:880-889`), matching TypeScript for JSON parse errors. OpenAI Chat, Anthropic, Bedrock Converse and Gemini's schema-invalid event therefore name the protocol constant for the error `route` rather than the configured route id, and their message text uses either the constant or the runtime label where TypeScript always uses `provider/route.id`. There is also no equivalent of the declared route body schema (`bodyFields` in `packages/ai/src/protocols/openai-chat.ts:222-249`, typed by `ProtocolBody.schema` in `packages/ai/src/route/protocol.ts:53-58`): the Rust builders construct `serde_json::Value` directly and only validate while projecting.

Reason: the port keeps protocol state machines as hand-written field readers so each provider's quirks stay explicit, and the replay check in `crates/ai/tests/all/replay.rs` compares produced request body bytes and emitted events rather than re-validating a schema. The consequence is that provider input TypeScript rejects as schema-invalid is emitted or ignored here, and error metadata names the protocol constant instead of the configured route. The corpus covers the resulting event streams and request bytes, not the rejected frames.
