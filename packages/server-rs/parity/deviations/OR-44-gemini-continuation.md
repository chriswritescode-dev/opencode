# OR-44: Gemini continuation does not resume a dropped connection or reprepare the request

TypeScript: `packages/ai/src/protocols/gemini.ts:802-862` wraps the first SSE execution in `respond`. It catches `Transport` errors whose code is not `Timeout`, records `dropped` and ends the frame stream (`Stream.catchIf`, lines 829-836). When a `continuationToken` is present and the finish reason is absent or `CONTINUATION`, it emits a `NextRequest` and calls `next(token)`, which runs `sse.prepare({ ...prepared.input, body: { ...prepared.input.body, continuationToken } })` and `sse.execute` again (lines 849-855), re-running auth, header preparation and the `http.body` overlay. A `CONTINUATION` finish with no token fails with `Gemini continued the response without a token` (lines 842-843) (pinned commit `73a0eae88de47f10068a0f9dc7a743638fa3d830`).

Rust: continuation is owned by `crates/ai/src/route/client.rs` `continue_response` (lines 298-313), called from `read_next` only after `frames.next()` has returned `None` normally (lines 253-268). A frame-stream error returns immediately (`client.rs:249-252`), so a dropped connection is never resumed and the partial response fails. `continue_response` clones the first prepared request, replaces the body with the stored JSON plus `continuationToken`, and rewrites only `content-length`, reusing the original URL and headers instead of re-running auth and header preparation. The stored body is `parts.json_body` from `crates/ai/src/route/compile.rs:69`, so the `http.body` overlay is preserved across continuation (fixed in this section). Gemini's protocol reports the token from `State::continuation` (`gemini.rs:1080-1101`) and still fails with `Gemini continued the response without a token` when `CONTINUATION` has no token.

Reason: the Rust client centralizes continuation so protocols do not need a transport wrapper, and a session-level executor will own reconnect policy. The consequence is that a Gemini response interrupted by a transport error fails here where TypeScript resumes it from the latest token, and a continued request keeps the original authentication and deployment headers rather than recomputing them. `crates/ai/tests/all/protocols.rs:235-290` covers the normal in-band continuation, including the preserved `http.body` overlay and the rewritten content length; no replay cassette drops a connection mid-response, so replay does not exercise the resume path.
