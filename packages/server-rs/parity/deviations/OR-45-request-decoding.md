# OR-45: modality request fields decode leniently

TypeScript: `packages/ai/src/image.ts:71-80` defines `ImageRequestSchema` with `aspect: Schema.optional(ImageAspectRatio)`, where `image.ts:65-66` aliases `Media.AspectRatio` and `packages/ai/src/media.ts:63-66` declares it to require `\d+(?:\.\d+)?:\d+(?:\.\d+)?`; `image.ts:183-190` decodes the normalized request with `Schema.decodeUnknownSync`, and `packages/ai/src/media-model.ts:116-129` turns that throw into `InvalidRequestError`. `packages/ai/src/video.ts:59-63` declares `VideoDuration` as `\d+(?:\.\d+)? seconds?`, `video.ts:52-53` declares `VideoAspectRatio` as `Media.AspectRatio | "auto"`, `video.ts:65-80` uses both in `VideoRequestSchema`, and `video.ts:146-153` validates through the same `tryRequest` path. `packages/ai/src/transcription.ts:71` declares `TranscriptionTimestamps = Schema.Literals(["none", "segment", "word"])`, used at `:80` and validated at `:190-197` (pin `73a0eae88de47f10068a0f9dc7a743638fa3d830`).

Rust: `crates/ai/src/modalities/image.rs:127-147` declares `ImageRequestInput.aspect: Option<String>` and copies it into `ImageRequest` (`:113-125`) without a request-time check, so a malformed spelling is forwarded, for example as `aspect_ratio` (`crates/ai/src/protocols/xai_images.rs:61-62`) or `aspectRatio` (`crates/ai/src/protocols/google_images.rs:77-78`). `crates/ai/src/modalities/video.rs:67-91` declares `duration` and `aspect` as `Option<String>`; `video.rs:208-227` parses a duration only at encode time, so `"8 minutes"` becomes `None` and is dropped (`crates/ai/src/protocols/xai_video.rs:247`). `crates/ai/src/modalities/transcription.rs:123-143` declares `timestamps: Option<String>`, sent verbatim as `timestamp_granularities` (`crates/ai/src/protocols/openai_transcription.rs:208-212`) and rejected only as a capability for models that do not list it (`:358-362`).

Reason: the port keeps request shapes as serde structs and defers each field's meaning to the protocol, so an unknown spelling reaches the route and either goes on the wire or fails as an unsupported-capability error instead of the pinned `InvalidRequest`. The replay corpus compares request bytes and emitted events for valid inputs only: every cassette uses a `\d+:\d+` aspect, `"word"` timestamps and `"N second(s)"` durations, so no cassette sends a malformed value. Probabilities and response fields are covered by `OR-45-response-decoding.md`. Enum-valued provider options are not part of this difference: the pinned `ReasoningEffort`, `knownString` and Vercel gateway schemas accept any string and reject an explicit `thinking: null`, matching the Rust `optional_string` readers.
