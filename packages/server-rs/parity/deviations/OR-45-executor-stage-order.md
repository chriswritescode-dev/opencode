# OR-45: credential resolution runs before request compilation, so a missing credential masks a request error

TypeScript: `packages/ai/src/route/client.ts:582-589` compiles a request in order — it first rejects `file:` references (`:582-587`), then builds the provider body with `route.body.from` (`:588`), and only then calls `route.prepareTransport` (`:589`), which the route forwards to `transport.prepare` (`:401-409`). The HTTP transport builds the URL and overlays `http.body` and then resolves auth last, at `packages/ai/src/route/transport/http.ts:36-44` (`Auth.toEffect(input.auth)` at `:44`), so a `MissingCredentialError` (`packages/ai/src/route/auth.ts:5-14`) can only be reported after the body builder has succeeded. A request with an unreadable `file:` reference, or whose body builder returns `InvalidRequest`, therefore fails with that request error even when the route's credential is missing.

Rust: `crates/ai/src/route/client.rs:41-47` starts `LlmClient::stream` in `Stage::Prepare`, and `:115-124` awaits `model.route.auth.prepare(...)` at `:117` before it calls `compile(...)` at `:121`. `Auth::prepare` resolves every credential kind, not only credential sources (`crates/ai/src/route/auth.rs:106-131`; `Credential::prepare` loads value, optional and env credentials at `:126-129`), and `compile` performs the `file:` rejection and the body build afterwards (`crates/ai/src/route/compile.rs:39-44`). The same credential is applied again while building the request parts (`crates/ai/src/route/transport/http.rs:72`), but the early `prepare` already decides which error is reported.

Reason: the Rust client resolves credentials before compiling so a credential source can obtain its token once per request; a source such as Google ADC needs the sender and an await, and its `load` only reads the prepared session (`crates/ai/src/providers/google_adc.rs:97-126`), so the transport cannot resolve it later on its own. The consequence is that a request with both a missing credential and an invalid body or local file reference reports the missing credential instead of `InvalidRequest`; TypeScript reports the request error. No cassette exercises this: `crates/ai/tests/corpus/google-adc.json` records the three missing-credential paths with otherwise valid requests, and no cassette pairs a missing credential with a body or local-file failure, so replay compares neither ordering.
