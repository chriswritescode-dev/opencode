# OR-44: Bedrock and SigV4 wire details differ in raw frames, cache warnings and signing

TypeScript: `packages/ai/src/protocols/bedrock-event-stream.ts:26,123,137-138` keeps a `rawBody` string on every frame, uses it as `Framing.body`, and `Framing.raw` strips it back out so `includeRaw` exposes the non-`rawBody` event. The Smithy codec produces `Uint8Array` for binary header values and an `Int64` wrapper for long values. `packages/ai/src/protocols/utils/cache.ts:22-28` logs `dropped N cache breakpoint(s)` and is called by `bedrock-converse.ts:606` and `anthropic-messages.ts:1045`. `packages/ai/src/protocols/utils/bedrock-auth.ts:68-80` passes caller headers into `AwsV4Signer` and returns every signed header, so a caller-supplied `host` stays in the output. Unsupported media uses the original `part.media.mediaType` in the message (`bedrock-media.ts:103,118`) (pinned commit `73a0eae88de47f10068a0f9dc7a743638fa3d830`).

Rust: `crates/ai/src/protocols/bedrock_event_stream.rs` stores `rawBody` as a string and returns it for `includeRaw` (`frame_event`, lines 218-260); because `crates/ai/src/route/client.rs` `raw_frame` parses the whole framed string, the exposed raw event still contains `rawBody`, where TypeScript's `Framing.raw` strips it. Its header parser emits binary values as a `Value::Array` of byte numbers and long values as a JSON number (`parse_headers`, lines 171-201), which only differs inside `rawBody`. `crates/ai/src/protocols/utils/bedrock_cache.rs` and the Anthropic `CacheControl` in `crates/ai/src/protocols/utils/cache.rs` count `dropped` but never log. `crates/ai/src/route/auth.rs` `sign_sigv4_request` (lines 196-241) drops any caller `host` header and signs the URL host instead, so the returned header list has no `host`. `crates/ai/src/protocols/utils/bedrock_media.rs` lowercases the media type before using it in the unsupported-media message (lines 11, 16-21).

Reason: the port has no logging dependency and uses plain `serde_json` values instead of Smithy's decoded header objects, and its signer reconstructs the host from the URL to guarantee canonical correctness. The replay corpus covers request body bytes, connect details, observations and emitted events; it does not assert log output, `rawBody` header value types, or the signed header list, so these differences are not observed by a check.
