# OR-45: Google Interactions continuation does not resume a continued or dropped stream

TypeScript: `packages/ai/src/protocols/google-interactions.ts:716-865` wraps the SSE execution in a `respond`/`next` loop. `respond` reads frames until `interaction.completed` (`:785`), swallows a non-timeout transport error and records it as `dropped` (`:786-792`), and then decides from the last status and token whether the stream can resume (`:793-833`). A `requires_continuation` status or a clean EOF while the interaction is still `in_progress` with a token emits a `NextRequest` (`:601-602`) and calls `next` (`:836-853`), which reprepares the request with `continuation_token`, and for stored interactions `previous_interaction_id` plus `input: undefined` (`:843-845`), then executes it again. It gives up after `MAX_STREAM_RECONNECTS_WITHOUT_PROGRESS = 3` reconnects without new content (`:35`, `:806-821`). `terminal` excludes a `requires_continuation` completion (`:887-890`), and the parser records the completion's usage without finishing (`:654-655`).

Rust: `crates/ai/src/protocols/google_interactions.rs:1162-1194` implements only the plain SSE state machine. `State::completed` (`:1073-1077`) stores the usage of a `requires_continuation` completion and returns no events, and `terminal` (`:1182-1193`) reports such a frame as non-terminal. `State::continued_usage` (`:913`) and the continued branch of `map_usage` (`:477-534`) implement the hop-accumulated usage shape, but nothing ever appends a hop: there is no `NextRequest` equivalent. Continuation is owned centrally by `crates/ai/src/route/client.rs`: `read_next` consults `ProtocolState::continuation` only after the frame stream ends normally (`:246-263`), and `continue_response` (`:287-303`) clones the first prepared request, inserts a single `continuationToken` string into the stored body, and rewrites `content-length`. Because the Interactions adapter never reports a continuation token, a `requires_continuation` completion reaches EOF and the route's incomplete-stream check reports `The provider response ended unexpectedly.` (`crates/ai/src/route/client.rs:276-279`, `:332-342`).

Reason: the Rust client owns framing and continuation for every protocol, and its continuation contract supports one string token appended to the previous body; a resumed Interactions request needs `previous_interaction_id`, an optional reset of `input`, and reconnect accounting, which is out of scope for this port. The consequence is that a `requires_continuation` status currently ends the stream without a finish (an incomplete-stream error) instead of resuming, and a dropped connection is never retried. None of the four `google-interactions/*` replay cassettes records a continuation, a dropped connection, or the DELETE cleanup request that the `continues-tool-results-with-previous-interaction-id` scenario issues outside the protocol, so replay does not exercise this path.
