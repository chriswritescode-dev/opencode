# OR-45: OpenAI decisions keeps unknown prompt-cache keys and names its inline route by protocol

TypeScript: `packages/ai/src/protocols/openai-decisions.ts:22-28` decodes provider options with an `Options` struct whose `promptCacheOptions` is `Schema.optional(Schema.Struct({ mode: Schema.optional(Schema.String), ttl: Schema.optional(Schema.String) }))`; `:58` runs that through `Schema.decodeUnknownEffect`, which drops unmodeled keys by default, and `:61-69` writes the decoded `prompt_cache_options` while spreading only the remaining raw top-level keys as `native` (`:62`). `packages/ai/src/route/decision.ts:76` makes the route id the configured `id: input.id`, `:109` gives each model that `route.id`, and `:117-119` builds the inline `MediaProtocol.identity` from it, so `packages/ai/src/route/media-protocol.ts:84` and `:208` carry the configured id into the inline route and its error metadata (`e54fbacb3d3aebc85f0e5ada0a5c490cc9333a91`).

Rust: `crates/ai/src/protocols/openai_decisions.rs:148-159` only checks that `mode` and `ttl` are strings when present, then clones the whole `promptCacheOptions` object into `prompt_cache_options`, so unknown nested keys reach the wire; `:84-91` still passes the other top-level keys through. `crates/ai/src/route/decision.rs:72-87` builds both the decode identity and the `InlineProtocol` from `protocol.id()` instead of the route's own `id` (kept at `:93`), and `crates/ai/src/media/route.rs:156-170` derives the `InlineRoute` id from that protocol id.

Reason: the port reads provider options with hand-written field readers, and the shared media inliner keys a route by its protocol, so neither re-encodes through a schema or keeps a separate route identity. The only `openai-decision` cassette (`decides-choice-score-and-predicate-questions-about-json-state`) sends no provider options, so it covers neither the nested-key stripping nor the pass-through; no decision cassette sets `promptCacheOptions`. Route and protocol ids are identical for every decision route ported today, including Baseten's `baseten-system-one`, so the identity difference is latent.
