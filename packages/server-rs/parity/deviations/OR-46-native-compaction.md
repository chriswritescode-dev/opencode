# OR-46: native compaction is rejected without checking the resolved route

TypeScript: `packages/core/src/model-resolver.ts:216-225` fails a resolved model with `UnsupportedCompactionError` only when the model's settings select native compaction (`model.settings?.compaction?.type === "native"`) and the resolved route has neither `compact.trigger` nor `compact.endpoint`; a route that declares either mechanism is accepted. Provider routes in the pinned TypeScript do declare it: the OpenAI Responses protocol route declares both (`packages/ai/src/protocols/openai-responses.ts:423-430`) and the `openai` package serves that route as its default model (`packages/ai/src/providers/openai.ts:32`, `:103`, `:179-184`); Azure copies the endpoint operation onto `azure-openai-responses` (`packages/ai/src/providers/azure.ts:52-53`, `:219-223`) and xAI declares its own on `xai-responses` (`packages/ai/src/providers/xai.ts:38-39`, `:110-112`). The core mapping sends catalog `@ai-sdk/azure` and `@ai-sdk/xai` models to those packages (`packages/core/src/aisdk-native.ts:117`, `:129`); the pinned test `packages/core/test/config/provider.test.ts:38-79` configures a provider with `package: "@opencode/ai/providers/openai/responses"` and `settings.compaction: { type: "native" }` and resolves it (`:72`), while the `openai/chat` override is rejected (`:75-78`). A model still on an AI SDK loader gets a route whose `compact` is `undefined` (`packages/core/src/aisdk.ts:384-385`) and is rejected by both servers (pinned `73a0eae88de47f10068a0f9dc7a743638fa3d830`).

Rust: `crates/catalog/src/resolver.rs:700-709`, in `finalize`, returns `Error::UnsupportedCompaction` for every `ProviderCompaction::Native(_)` setting and never reads the route. `crates/ai/src/route/model.rs:28-39` gives `Route` no compaction field; the only mention of compaction under `crates/ai/src/route` is the `LlmEvent::Compaction` event name (`crates/ai/src/route/client.rs:385`), so the resolver has nothing to consult. Compaction exists only as request builders (`OR-44-compaction-execution.md`). `finalize` is reached from every language-model return in `from_catalog_model` (`crates/catalog/src/resolver.rs:194`, `:208`, `:216`) and is not applied to media models, matching where TypeScript runs its check.

Reason: OR-44 built compaction and checkpoint requests but never posts or decodes them (`OR-44-compaction-execution.md`), so no Rust route advertises a compaction capability and the resolver rejects every native policy rather than accepting one the executor cannot honour. The outcome differs from the pin for models on routes that do declare support: the OpenAI Responses, Azure and xAI routes above resolve in TypeScript and fail with `UnsupportedCompaction` here. The check must consult the route once a capability exists. The Rust resolver test `rejects_native_provider_compaction` (`crates/catalog/tests/all/resolver.rs:1293-1314`) expects the rejection for an OpenAI Responses model whose pinned counterpart resolves at `packages/core/test/config/provider.test.ts:72`, and no parity scenario sets a `native` compaction setting, so parity does not exercise the difference.
