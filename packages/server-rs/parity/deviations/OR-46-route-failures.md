# OR-46: integration and credential routes answer typed errors where TypeScript dies

TypeScript: `Integration.oauth.connect` dies with `OAuth method not found: <integration>/<method>` when the integration has no implementation for the method (`packages/core/src/integration.ts:572-575`), `command.connect` dies when the method is missing or its `command` array is empty (`:622-628`), and `connection.key` dies with `Key method not found: <integration>` when the integration has no key method (`:717-722`); each `Effect.die` reaches the client as HTTP 500. `oauth.complete` dies with `OAuth attempt already completing: <attempt>` for a pending attempt whose `completing` flag is already set (`:812-813`), and auto-mode attempts are created with that flag set (`:590`), so completing one without a submit reaches the die, while an attempt that is no longer pending returns without content (`:800-807`). The credential routes fail the same way: a missing global config Location is a die in `credential.create` (`packages/server/src/handlers/credential.ts:20,35`) and an `Effect.orDie` in `credential.remove` (`:69`), and every credential read or write ends in a die, so a storage failure is a 500 as well (`packages/core/src/credential.ts:109-116`, `:132-140`). The command route pre-checks the method id and answers 404 before calling the service (`packages/server/src/handlers/integration.ts:253-258`), so its core die is reachable only for a command method whose command array is empty.

Rust: `ConnectionService::key` returns `AuthorizationError` carrying `Key method not found: <integration>` when no key method exists (`crates/catalog/src/integration/connect.rs:36-60`, message at `:44-49`), and credential persistence failures go through the same error (`create` at `:98-119`, mapping at `:117`). `OAuthService::connect` returns `AttemptError::MethodNotFound` (`crates/catalog/src/integration/attempt.rs:133-138`), `complete` returns `Ok(())` for a terminal attempt (`:265`) and `Action::None` for an auto attempt without a submit or a code-mode attempt that is already completing (`:275-291`), keeping `CodeRequired` for a missing code (`:289`), and `CommandService::connect` returns `CommandError::MethodNotFound` for a missing method or an empty command (`crates/catalog/src/integration/command.rs:110-121`). `crates/http/src/handlers/integration.rs` maps these to 404 `IntegrationMethodNotFoundError` with `Integration method not found: <method>` (`:391`, `:435-446`), 400 `InvalidRequestError` with kinds `integration_authorization` and `integration_code_required` (`:375-381`, `:388-390`), and 204 for `Ok(())` (`:199-202`), reusing the message texts of the TypeScript handlers (`packages/server/src/handlers/integration.ts:184`, `:216`, `:219-225`, `:257`). The credential handlers map a missing global config Location to 404 `LocationNotFoundError` through `location_error` (`crates/http/src/handlers/credential.rs:38-41`, `:125-128`, `crates/http/src/services.rs:323-346`) and any other persistence failure to 503 `ServiceUnavailableError` from `service_unavailable` (`crates/http/src/services.rs:361-371`), whose payload names the failing subsystem: `credential` for list, create, update and activate (`crates/http/src/handlers/credential.rs:29,64,75,105,116`) and `integration` for a connectable check or removal (`crates/http/src/handlers/integration_policy.rs:19`, `crates/http/src/handlers/credential.rs:131`).

Reason: the port represents each of these local failures as a typed error so the handler stays total and a client can tell an unknown method, an unknown attempt and a repeated completion apart, while TypeScript leaves an unmatched method, a repeated completion and a storage failure as `Effect.die`. `integration-routes` covers the key-connect success, an external method that does not exist (400) and unknown OAuth and command attempts (404), and `credential-routes` covers create, a duplicate id (409), update, activate and remove; no scenario connects an unknown OAuth method, connects to an integration without a key method, sends a command method with an empty command, completes an OAuth attempt twice, or forces a credential storage or global config failure.
